# PostgreSQL with Java and Spring Boot

Research checked: 2026-11-12

Previous: [PostgreSQL SQL Lab](sql-lab.md). Start its database and run the table
creation and seed statements first. This guide uses the same `books` table.
The examples were checked with PostgreSQL 18.6, Spring Boot 3.5.7, and Java 25;
check compatibility and APIs when choosing other versions.

## The Stack

```text
HTTP client -> Spring Boot -> Spring Data JPA -> Hibernate -> JDBC -> PostgreSQL
                                                        PostgreSQL JDBC driver
```

**JDBC** is Java's API for database connections and SQL. The PostgreSQL JDBC
driver implements that API for PostgreSQL. **JPA** is a Java persistence
specification; **Hibernate** is one implementation that maps Java objects to
database rows. **Spring Data JPA** adds repositories; Spring Boot configures
the connection pool, driver, and persistence components from properties.
You can use JDBC directly, JPA, or both, choosing the approach that fits the
query and application. JPA does not remove the need to understand SQL.

## 1. Create a Project

Install a JDK and Maven, or use the Maven wrapper generated by Spring
Initializr. At [Spring Initializr](https://start.spring.io/), generate a Maven
Java project using a supported Spring Boot release and JDK, with **Spring Web**,
**Spring Data JPA**, and **PostgreSQL Driver**. The Spring Boot parent manages
compatible dependency versions. The generated `pom.xml` should include:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
```

This example uses Java records, which require Java 16 or newer; use the JDK
required by your chosen Boot version. Put the Java files below in package
`example.bookstore` under `src/main/java/example/bookstore`, replacing the
generated application class. Configure `src/main/resources/application.properties`:

```properties
spring.datasource.url=${DB_URL:jdbc:postgresql://localhost:5432/bookstore}
spring.datasource.username=${DB_USER:bookstore}
spring.datasource.password=${DB_PASSWORD:bookstorepass123}
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.open-in-view=false
```

The URL identifies the host, port, and database; credentials identify the
role. `validate` checks Hibernate's mapped schema at startup instead of creating
or updating tables. It does not verify every constraint or replace migrations.
Create the lab schema first. The defaults and superuser account are for local
learning only; in production use least-privilege roles, secret management,
appropriate TLS, backups, and migrations. If the application runs in another
container, `localhost` refers to that container, not the database container.

## 2. Map a Table and Define a Repository

`Book.java`:

```java
package example.bookstore;

import java.math.BigDecimal;
import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

@Entity
@Table(name = "books")
public class Book {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String isbn;

    @Column(nullable = false)
    private String title;

    @Column(nullable = false, precision = 10, scale = 2)
    private BigDecimal price;

    protected Book() {
    }

    public Book(String isbn, String title, BigDecimal price) {
        this.isbn = isbn;
        this.title = title;
        this.price = price;
    }

    public Long getId() { return id; }
    public String getIsbn() { return isbn; }
    public String getTitle() { return title; }
    public BigDecimal getPrice() { return price; }
}
```

`@Entity` maps a Java class, `@Table` selects the table, and `@Id` identifies
the key. The `IDENTITY` strategy uses the database-generated ID. `BigDecimal`
is appropriate for exact decimal values such as prices; avoid `double` for
money. The database constraints from the lab remain the final enforcement
point, including for non-JPA clients.

`BookRepository.java`:

```java
package example.bookstore;

import org.springframework.data.jpa.repository.JpaRepository;

public interface BookRepository extends JpaRepository<Book, Long> {
}
```

`JpaRepository<Book, Long>` supplies `findAll`, `findById`, `save`, and other
operations. Spring Data can also derive queries from method names or execute
explicit queries. Repository methods are convenient, but understand the SQL
and number of queries produced, especially when mapping relationships.

## 3. Expose a Small HTTP API

`BookstoreApplication.java`:

```java
package example.bookstore;

import java.math.BigDecimal;
import java.util.List;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.data.domain.Sort;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestController;

@SpringBootApplication
public class BookstoreApplication {
    public static void main(String[] args) {
        SpringApplication.run(BookstoreApplication.class, args);
    }
}

record CreateBookRequest(String isbn, String title, BigDecimal price) {
}

@RestController
@RequestMapping("/books")
class BookController {
    private final BookRepository books;

    BookController(BookRepository books) {
        this.books = books;
    }

    @GetMapping
    List<Book> all() {
        return books.findAll(Sort.by("title"));
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    Book create(@RequestBody CreateBookRequest request) {
        return books.save(new Book(request.isbn(), request.title(), request.price()));
    }
}
```

Run `./mvnw spring-boot:run` from the generated project directory. In another
terminal:

```bash
curl http://localhost:8080/books
```

The response contains the seeded Graphs and SQL Basics books, with IDs, ISBNs,
titles, and prices. IDs are generated and can vary.

```bash
curl -X POST http://localhost:8080/books \
  -H 'Content-Type: application/json' \
  -d '{"isbn":"isbn-java","title":"Java Basics","price":20.00}'
```

The response has status 201 and includes the new book with its generated ID.
Query `SELECT * FROM books ORDER BY title;` in `psql` to see the same data.
Repeating the POST with the same ISBN violates the unique constraint. This
minimal example does not translate database errors into friendly HTTP errors,
validate requests, authenticate users, or paginate results; add those before
real use. Use DTOs and deliberately load data for more complex entities rather
than exposing arbitrary JPA relationships directly as JSON.

## 4. Use JDBC Directly

The following complete class also works in the same project. It connects using
the local lab defaults and accepts `DB_URL`, `DB_USER`, and `DB_PASSWORD`
environment overrides. Run it from the project directory with
`./mvnw compile exec:java -Dexec.mainClass=example.bookstore.JdbcExample`.
The Maven exec plugin resolves the PostgreSQL driver from the runtime classpath.

`JdbcExample.java`:

```java
package example.bookstore;

import java.math.BigDecimal;
import java.sql.DriverManager;

public class JdbcExample {
    public static void main(String[] args) throws Exception {
        String url = System.getenv().getOrDefault("DB_URL", "jdbc:postgresql://localhost:5432/bookstore");
        String user = System.getenv().getOrDefault("DB_USER", "bookstore");
        String password = System.getenv().getOrDefault("DB_PASSWORD", "bookstorepass123");

        try (var connection = DriverManager.getConnection(url, user, password);
             var statement = connection.prepareStatement(
                 "SELECT title, price FROM books WHERE price >= ? ORDER BY title")) {
            statement.setBigDecimal(1, new BigDecimal("20.00"));
            try (var rows = statement.executeQuery()) {
                while (rows.next()) {
                    System.out.println(rows.getString("title") + ": " + rows.getBigDecimal("price"));
                }
            }
        }
    }
}
```

With the initial seed, it prints `Graphs: 25.00`. After the API example it also
prints `Java Basics: 20.00`. `?` is a JDBC parameter; `setBigDecimal` binds its
value without concatenating SQL. Use parameters for untrusted values. JDBC
parameters do not generally represent SQL identifiers such as table names;
choose dynamic identifiers from an allowlist. Try-with-resources closes the
result set, statement, and connection. Outside Spring Boot, add
`org.postgresql:postgresql` at a compatible version to your Java project's
runtime dependencies; no Spring dependency is needed for this class.

## 5. Transactions and Production Considerations

- Use a Spring service with `@Transactional` around operations that must succeed
  together, such as creating an order and its items. Exceptions and rollback
  rules matter; do not assume two separate HTTP requests share a transaction.
  In standalone JDBC, disable auto-commit and explicitly commit or roll back.
- Boot normally provides a pooled `DataSource`. Borrow and return connections
  promptly; size pools based on the database's total connection budget across
  instances, not just one application. See [Connection Exhaustion in Tests](../../spring-boot/testing/database-connection-exhaustion.md).
- Manage schema changes with a migration tool such as [Flyway](../flyway.md),
  and coordinate migrations with application deployment. Do not rely on
  Hibernate `create`, `create-drop`, or automatic updates for production schema
  history. The lab uses manually created tables and `validate`.
- Enforce constraints, parameterize queries, inspect query plans, and test with
  representative data. A unique constraint protects against concurrent inserts
  in a way that checking first in Java alone cannot.
- Test against real PostgreSQL, for example with [PostgreSQL Testcontainers](../../spring-boot/testing/shared-postgres-testcontainers.md),
  not only an in-memory substitute. Plan and test backup/restore, monitoring,
  least-privilege access, encryption, and connection limits.

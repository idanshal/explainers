# PostgreSQL and SQL: A Hands-On Lab

Research checked: 2026-11-12

Previous: [PostgreSQL Fundamentals](fundamentals.md). Next:
[PostgreSQL with Java and Spring Boot](java-spring-boot.md).

This lab uses a small bookstore and PostgreSQL 18.6. Run its sections in order
against a fresh, local database. SQL does not require Java. Statements ending
in semicolons are SQL; backslash commands belong to the `psql` client.

## 1. Start PostgreSQL

Install and start [Docker Desktop](https://www.docker.com/products/docker-desktop/)
or another working Docker engine. In a terminal, run:

```bash
docker run --name postgres-lab -d \
  -p 127.0.0.1:5432:5432 \
  -e POSTGRES_USER=bookstore \
  -e POSTGRES_PASSWORD=bookstorepass123 \
  -e POSTGRES_DB=bookstore \
  -v postgres-lab-data:/var/lib/postgresql \
  postgres:18.6
```

Docker downloads the image on first use. The example account is a superuser and
the password is for local learning only. The port is bound to your computer,
not all network interfaces. `/var/lib/postgresql` is the documented mount point
for the official PostgreSQL **18+** image; older image versions differ. The
named volume persists data after the container is removed. Initialization
variables take effect only for an empty data directory: reusing an existing
volume does not change its user, password, or database.

Connect using the `psql` client inside the container:

```bash
docker exec -it postgres-lab psql -U bookstore -d bookstore
```

You should see a `bookstore=#` prompt. This local connection uses the image's
Unix-socket authentication; applications connecting over TCP must authenticate.
If the server is still starting, check `docker logs postgres-lab` and retry.
Paste each SQL block into `psql` separately; a command executes when the
terminating `;` is entered. You can also use a local `psql` or a GUI such as
pgAdmin with host `localhost`, port `5432`, database and user `bookstore`, and
password `bookstorepass123`. Installing the server directly or using a managed
PostgreSQL service are alternatives; their setup, TLS, and credentials differ.

Try `\conninfo` to see the connection, `\dt` to list tables, `\d books` to
describe a table after creation, and `\q` to quit. These are `psql` commands,
not SQL; enter them without a semicolon.

## 2. Create the Tables

```sql
CREATE TABLE customers (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name text NOT NULL,
    email text NOT NULL UNIQUE
);

CREATE TABLE books (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    isbn text NOT NULL UNIQUE,
    title text NOT NULL,
    price numeric(10, 2) NOT NULL CHECK (price >= 0)
);

CREATE TABLE orders (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    order_code text NOT NULL UNIQUE,
    customer_id bigint NOT NULL REFERENCES customers(id)
);

CREATE TABLE order_items (
    order_id bigint NOT NULL REFERENCES orders(id),
    book_id bigint NOT NULL REFERENCES books(id),
    quantity integer NOT NULL CHECK (quantity > 0),
    PRIMARY KEY (order_id, book_id)
);
```

`bigint` holds whole numbers, `numeric(10, 2)` holds exact decimal amounts,
and `text` holds strings. Identity columns generate IDs when omitted; the
primary key additionally enforces uniqueness and non-null values. `UNIQUE`,
`NOT NULL`, `CHECK`, and foreign keys enforce rules in the database, including
for writes from outside your application. The composite primary key prevents
the same book appearing twice in one order. `CREATE TABLE` is not repeatable
against existing tables; keep using the same tables for the rest of the lab.

## 3. Add Sample Data

```sql
INSERT INTO customers (name, email) VALUES
    ('Alice', 'alice@example.test'),
    ('Bob', 'bob@example.test')
ON CONFLICT (email) DO NOTHING;

INSERT INTO books (isbn, title, price) VALUES
    ('isbn-graph', 'Graphs', 25.00),
    ('isbn-sql', 'SQL Basics', 15.00)
ON CONFLICT (isbn) DO NOTHING;

INSERT INTO orders (order_code, customer_id)
SELECT 'order-100', id FROM customers WHERE email = 'alice@example.test'
ON CONFLICT (order_code) DO NOTHING;

INSERT INTO order_items (order_id, book_id, quantity)
SELECT orders.id, books.id, items.quantity
FROM orders
JOIN (VALUES ('isbn-graph', 2), ('isbn-sql', 1)) AS items(isbn, quantity) ON true
JOIN books ON books.isbn = items.isbn
WHERE orders.order_code = 'order-100'
ON CONFLICT (order_id, book_id) DO NOTHING;
```

The seed looks up generated IDs instead of assuming their values. Rerunning it
does not insert duplicates with these keys, but `DO NOTHING` does not reset
changed names, prices, or quantities. If the schema already contains different
data, expected results can differ. `INSERT ... RETURNING id` returns generated
values; IDs can have gaps and should not be assumed to be sequential.

## 4. Read, Filter, and Sort

```sql
SELECT title, price FROM books ORDER BY price DESC;
```

Expected: Graphs / 25.00, then SQL Basics / 15.00. `DESC` means descending;
`ASC` means ascending. Without `ORDER BY`, results have no guaranteed order.

```sql
SELECT title, price
FROM books
WHERE price >= 20 AND title LIKE 'G%';
```

Expected: Graphs / 25.00. `WHERE` filters rows. `LIKE 'G%'` matches text
starting with `G`; `%` represents any sequence. Use `IS NULL` or `IS NOT NULL`
for missing values, not `= NULL`.

## 5. Join Tables and Aggregate

```sql
SELECT c.name, b.title, item.quantity, b.price * item.quantity AS line_total
FROM customers AS c
JOIN orders AS o ON o.customer_id = c.id
JOIN order_items AS item ON item.order_id = o.id
JOIN books AS b ON b.id = item.book_id
WHERE o.order_code = 'order-100'
ORDER BY b.title;
```

Expected: Alice / Graphs / 2 / 50.00 and Alice / SQL Basics / 1 / 15.00. The
aliases `c`, `o`, `item`, and `b` are shorthand for the tables. An inner `JOIN`
keeps matching rows; `LEFT JOIN` can keep rows on the left without a match.

```sql
SELECT c.name, SUM(b.price * item.quantity) AS order_total
FROM customers AS c
JOIN orders AS o ON o.customer_id = c.id
JOIN order_items AS item ON item.order_id = o.id
JOIN books AS b ON b.id = item.book_id
WHERE o.order_code = 'order-100'
GROUP BY c.name;
```

Expected: Alice / 65.00. `SUM` combines values, while `GROUP BY` specifies the
groups. This teaching schema uses the current book price; real orders typically
store the agreed unit price on each order item to preserve purchase history.

## 6. Update, Delete, and Roll Back

Run the following together. The final query shows the original price because
`ROLLBACK` undoes the transaction's changes.

```sql
BEGIN;
UPDATE books SET price = 30.00 WHERE isbn = 'isbn-graph';
SELECT title, price FROM books WHERE isbn = 'isbn-graph';
ROLLBACK;
SELECT title, price FROM books WHERE isbn = 'isbn-graph';
```

Expected: 30.00 inside the transaction, then 25.00 after rollback. `COMMIT`
would persist the changes instead. If a statement fails inside an explicit
transaction, PostgreSQL marks that transaction failed until `ROLLBACK` (or a
rollback to an appropriate savepoint).

```sql
BEGIN;
DELETE FROM order_items
WHERE order_id = (SELECT id FROM orders WHERE order_code = 'order-100')
  AND book_id = (SELECT id FROM books WHERE isbn = 'isbn-sql');
SELECT COUNT(*) AS remaining FROM order_items;
ROLLBACK;
```

Expected: `remaining` is 1 inside the transaction; rollback restores the item.
Always inspect the `WHERE` condition before `UPDATE` or `DELETE`: omitting it
can change every row. Foreign keys may prevent deleting a referenced row.

## 7. Inspect and Experiment

Try finding Bob's orders with `LEFT JOIN`, adding a book with `RETURNING id`,
or counting items per order. Use `EXPLAIN SELECT ...` to inspect a plan;
`EXPLAIN ANALYZE` **executes** the statement, including writes. A tiny teaching
dataset may produce a sequential scan even when an index exists. See
[Foreign Keys and Indexes](../foreign-keys-and-indexes.md) for constraint and
index tradeoffs. In application code, bind parameters instead of concatenating
untrusted input; the [Java guide](java-spring-boot.md) shows how.

## 8. Stop and Clean Up

Exit `psql` with `\q`. From your terminal:

```bash
docker stop postgres-lab
docker start postgres-lab
```

Stopping and starting preserves the data. To remove the container and
**permanently delete this lab's data**, use these only when it is no longer
needed:

```bash
docker rm -f postgres-lab
docker volume rm postgres-lab-data
```

If port 5432 is occupied, use a different host port such as
`-p 127.0.0.1:5433:5432` and connect clients to 5433. If the container name is
already taken, choose a new one. An existing volume retains its original
credentials; environment variables do not reset them. A volume is persistence,
not a backup.

# Neo4j with Java and Spring Boot

Research checked: 2026-11-12

Previous: [Neo4j and Cypher Lab](neo4j-cypher-lab.md). Start the database and
run its constraint and seed first; this guide uses the same people and follows.
The examples were checked with Spring Boot 3.5.7, Java 25, and Neo4j 2026.10.2;
check compatibility and APIs when choosing other versions.

## The Stack

```text
HTTP client -> Spring Boot application -> Neo4j Java driver -> Bolt -> Neo4j
                          |
                   Spring Data Neo4j
```

The **Java driver** connects to Neo4j, sends parameterized Cypher, and returns
records. **Spring Data Neo4j** adds Spring repositories and maps graph data to
Java domain objects. Spring Boot configures these components from application
properties. You can use the driver directly, Spring Data, or both in one app.
Spring Data Neo4j is not JPA: Neo4j is not a relational database, so JPA
annotations, SQL, and Hibernate are not the API used here.

## 1. Create a Spring Boot Project

Install a JDK and Maven, or use the Maven wrapper generated by Spring Initializr.
At [Spring Initializr](https://start.spring.io/), generate a **Maven, Java**
project using a supported Spring Boot release and Java version, with **Spring
Web** and **Spring Data Neo4j**. The Spring Boot parent manages compatible
dependency versions. The following dependencies will be in `pom.xml`:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-neo4j</artifactId>
</dependency>
```

Spring Data's starter brings in the driver; do not independently pin a driver
version in this Boot project without checking compatibility. The examples below
use Java text blocks, available since Java 15; use the JDK required by your
chosen Boot version. Put all Java files in the same `example.graph` package
under `src/main/java/example/graph`, replacing the generated application class.

Configure `src/main/resources/application.properties`:

```properties
spring.neo4j.uri=${NEO4J_URI:bolt://localhost:7687}
spring.neo4j.authentication.username=${NEO4J_USERNAME:neo4j}
spring.neo4j.authentication.password=${NEO4J_PASSWORD:graphpass123}
spring.data.neo4j.database=neo4j
```

These defaults match the local lab only. For a real deployment, provide secrets
via environment variables or your secret manager, enable encryption as
appropriate, restrict network access, and use a least-privilege account. For
Aura, use the provided encrypted URI and credentials; the database name may
differ. `localhost` refers to the application's own environment: if the app
runs in another container, use a reachable Docker network address instead.

## 2. Map a Person and Query the Graph

The sample intentionally maps only person properties. It does **not** map
`FOLLOWS` as a Java collection; the custom query traverses those relationships
and returns matching person nodes. Add each file under the package above.

`Person.java`:

```java
package example.graph;

import org.springframework.data.annotation.Id;
import org.springframework.data.neo4j.core.schema.Node;

@Node("Person")
public class Person {
    @Id
    private String id;
    private String name;

    public Person() {
    }

    public String getId() {
        return id;
    }

    public void setId(String id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}
```

`@Node` identifies the graph label and `@Id` uses the application's stable ID,
not an internal Neo4j ID. The lab's unique constraint protects that ID in the
database. The application must also ensure it is present and valid; the
uniqueness constraint alone does not require the property to exist.

`PersonRepository.java`:

```java
package example.graph;

import java.util.List;
import org.springframework.data.neo4j.repository.Neo4jRepository;
import org.springframework.data.neo4j.repository.query.Query;
import org.springframework.data.repository.query.Param;

public interface PersonRepository extends Neo4jRepository<Person, String> {
    @Query("""
        MATCH (:Person {id: $id})-[:FOLLOWS]->(:Person)-[:FOLLOWS]->(candidate:Person)
        RETURN DISTINCT candidate
        ORDER BY candidate.name
        """)
    List<Person> findTwoHopsAway(@Param("id") String id);
}
```

`Neo4jRepository<Person, String>` supplies operations including `findById` and
`save`. `@Query` supplies Cypher when the desired graph pattern is more
expressive than a derived method name. `@Param` binds `$id` as data, not Cypher
text. `DISTINCT` removes duplicate candidate nodes reached through multiple
paths. It does not exclude someone already followed or the starting person.

`GraphApplication.java`:

```java
package example.graph;

import java.util.List;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@SpringBootApplication
public class GraphApplication {
    public static void main(String[] args) {
        SpringApplication.run(GraphApplication.class, args);
    }
}

@RestController
@RequestMapping("/people")
class PersonController {
    private final PersonRepository people;

    PersonController(PersonRepository people) {
        this.people = people;
    }

    @GetMapping("/{id}/two-hops")
    List<Person> twoHops(@PathVariable("id") String id) {
        return people.findTwoHopsAway(id);
    }
}
```

Run the app from the project directory with `./mvnw spring-boot:run` and try:

```bash
curl http://localhost:8080/people/alice/two-hops
```

With the original seed, the response is `[ { "id": "carol", "name": "Carol" } ]`
(whitespace may differ). An unknown ID returns an empty list in this example.
The endpoint is intentionally minimal: add authentication, validation, error
handling, pagination, and appropriate authorization for a real application.
Re-run the lab seed if you deleted sample nodes or relationships.

## 3. Use the Java Driver Directly

The Boot starter already configures a reusable `org.neo4j.driver.Driver` bean.
This example shows the same query without object mapping. It can be added as a
class in the same project and injected where needed:

```java
package example.graph;

import java.util.List;
import java.util.Map;
import org.neo4j.driver.Driver;
import org.neo4j.driver.QueryConfig;
import org.springframework.stereotype.Service;

@Service
public class FollowLookup {
    private final Driver driver;

    public FollowLookup(Driver driver) {
        this.driver = driver;
    }

    public List<String> namesTwoHopsAway(String id) {
        var result = driver.executableQuery("""
            MATCH (:Person {id: $id})-[:FOLLOWS]->(:Person)-[:FOLLOWS]->(candidate:Person)
            RETURN DISTINCT candidate.name AS name
            ORDER BY name
            """)
            .withParameters(Map.of("id", id))
            .withConfig(QueryConfig.builder().withDatabase("neo4j").build())
            .execute();
        return result.records().stream()
            .map(record -> record.get("name").asString())
            .toList();
    }
}
```

This uses the driver's `executableQuery` API; check the driver version managed
by your chosen Boot release and its documentation. The database name above is
explicit and must be adjusted for other deployments. The configured driver is
managed by Spring; don't close it per request. Outside Spring, add the
`org.neo4j.driver:neo4j-java-driver` dependency using a compatible version,
create one `GraphDatabase.driver(uri, AuthTokens.basic(user, password))`,
reuse it, and close it when the application shuts down. Driver queries can
handle transient failures with retries; write callbacks and external side
effects must therefore be designed for retry safety.

## 4. Transactions, Mapping, and Production

- Use transactions for a group of changes that must succeed or fail together;
  a single query is transactional too. With Spring Data use the configured
  Neo4j transaction manager and `@Transactional` on a service method. Verify
  transaction boundaries when mixing raw driver sessions with Spring Data;
  do not assume separately created sessions automatically share a transaction.
- To map relationships, use `@Relationship` and, when relationship properties
  are needed, `@RelationshipProperties` with `@RelationshipId` and
  `@TargetNode`. Direction matters. Custom queries returning entities with
  relationships must provide the nodes and relationships required for mapping.
- Be careful saving partially loaded relationship graphs: Spring Data may treat
  the mapped object as the desired state and remove relationships absent from
  it. Design aggregate boundaries and queries intentionally; do not load a
  partial graph and blindly save it. The sample maps no relationship fields.
- Parameterize values, add appropriate constraints and indexes, and inspect
  `EXPLAIN`/`PROFILE` on representative data. Bound path lengths and paginate
  potentially large results. The driver's simple query API eagerly collects
  records; use sessions and streaming for large results.
- Plan schema and data migrations explicitly. Set up backups and test restores,
  monitoring, access controls, and TLS. A Docker volume is persistence, not a
  backup. Test against a real Neo4j instance, for example with Testcontainers,
  and verify the edition and version you deploy.

# npm: Packages, Dependencies, and Scripts

npm is the package manager commonly used with Node.js. It can download packages from a registry, record a project's dependencies, and run commands defined by the project. **Node.js** is the JavaScript runtime that executes JavaScript outside a browser; npm does not run the application itself.

This guide creates a small Node.js project, adds a dependency, and follows the files npm uses to make installs repeatable. It assumes macOS/Linux shell commands; the npm commands also work in PowerShell.

## Before You Start

Install a supported Node.js release. The standard Node.js installer includes npm. Check both commands:

```bash
node --version
npm --version
```

The commands should print version numbers. If either is not found, install Node.js and open a new terminal so the updated `PATH` is loaded. npm needs registry access to download packages that are not already cached.

## 1. Create a Project

Make a directory and create a `package.json` file:

```bash
mkdir hello-npm
cd hello-npm
npm init -y
```

`npm init` asks questions and writes project metadata. The `-y` option accepts the defaults, which you can edit later. A project can start with this small structure:

```text
hello-npm/
  package.json
```

`package.json` is the project's manifest. It describes the project, its dependency version ranges, and named scripts. It is not the package's source code, and npm does not require every project to publish a package to the registry.

## 2. Add and Use a Package

Install Day.js as an application dependency:

```bash
npm install dayjs
```

npm adds a version range for `dayjs` to `dependencies`, resolves the package, and records the resolved dependency tree in `package-lock.json`. It also places the installed package files in `node_modules/`.

Create `index.js`:

```js
const dayjs = require("dayjs");

console.log(`Today is ${dayjs().format("YYYY-MM-DD")}`);
```

Run the file with Node.js:

```bash
node index.js
```

This illustrates the two tools' roles: `npm install` manages the dependency, and `node` executes the application.

### Runtime and Development Dependencies

Packages needed by the application when it runs belong in `dependencies`. Tools used to develop, test, or build it usually belong in `devDependencies`:

```bash
npm install --save-dev eslint
```

The `--save-dev` option records the package under `devDependencies`. In production deployments, development dependencies can be omitted; make sure anything needed at runtime is listed under `dependencies` instead.

## 3. Add a Script

Scripts give common project commands stable names. Add a `start` script to `package.json`:

```json
{
  "scripts": {
    "start": "node index.js"
  }
}
```

Keep the other fields generated by `npm init` and added by `npm install`; the snippet shows only the part to add. Run the script with:

```bash
npm start
```

For other named scripts, use `npm run <name>`, for example `npm run lint`. Use `npm run` to list the scripts in the current package. npm also gives `npm test` and `npm start` shorthand forms for those script names.

## 4. Understand the Install Files

The project now has three important npm files or directories:

| Path | Purpose | Commit it? |
| --- | --- | --- |
| `package.json` | Project metadata, dependency ranges, and scripts. | Yes. |
| `package-lock.json` | Exact resolved dependency tree used for installs. | Yes, for an application. |
| `node_modules/` | Installed package files on this machine. | No; recreate it from the manifest and lockfile. |

When a project has a lockfile, `npm install` uses its resolved versions when they satisfy the ranges in `package.json`. If they do not, npm resolves a compatible tree and updates the lockfile. Commit changes to both manifest and lockfile together so teammates can review dependency updates.

To install a project's dependencies after cloning it, run:

```bash
npm install
```

For a clean, automated install in CI or deployment, use:

```bash
npm ci
```

`npm ci` requires a lockfile that agrees with `package.json`. It removes an existing `node_modules/`, installs the locked tree, and does not rewrite either manifest file. If it reports a mismatch, update the dependency files intentionally with `npm install`, review the changes, and commit them; do not delete the lockfile just to make CI pass.

## 5. Run a Package Command

Some packages provide command-line programs. `npm exec` runs a package command in the project context:

```bash
npm exec -- eslint .
```

The `--` separates npm options from the command's arguments. `npx` is also commonly used for this purpose:

```bash
npx eslint .
```

If the command is not already available locally, npm may fetch a package to run it. Check the package name and source before executing a command from a package you do not know; installing or running third-party packages can execute their code.

## Common Problems

- **`npm` or `node` is not found:** Install Node.js, then open a new terminal and check that its install location is on `PATH`.
- **A dependency cannot be resolved:** Check the package name, network access, and any project or user `.npmrc` registry settings.
- **`npm ci` fails on a lockfile mismatch:** Use `npm install` to reconcile the files, inspect the resulting changes, and commit `package.json` and `package-lock.json` together.
- **A script is not found:** Run it from the package directory and check its exact name under `scripts` in `package.json`.
- **A package command is not found:** Confirm the package is installed in this project and that its documented executable name matches the command you are running.
